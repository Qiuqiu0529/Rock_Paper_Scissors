# 石头剪刀布分阶段比赛模拟

需要 Python 3.10 或更新版本，不需要第三方库。以下命令在本文件所在目录运行。

三种拳完全对称的无奖励版本另见 `rps_original.py` 和 `README_original.md`：同时取消剪刀额外积分和剪刀次数同分优先。

可配置更多策略、多阶段赛制及任意计分的统一版本另见 `rps_simulator.py` 和 `README_simulator.md`，完整包为 `rps_simulator_package.zip`。

## 两阶段赛制

| 阶段 | 参赛人数 | 每人场次数 | 阶段总场数 | 晋级人数 |
|---|---:|---:|---:|---:|
| 初赛 | 100 | 5 | 250 | 30 |
| 决赛 | 30 | 9 | 135 | 10 |

共 385 场、14 轮，比原来 4950 场减少约 92.2%。如果同轮同时进行，初赛每轮 50 场、决赛每轮 15 场。
初赛淘汰者打 5 场；进入决赛者一共打 14 场。

- 每阶段随机编排：每轮每人恰好打一场，同一阶段内不会重复遇到同一对手。
- 实现方法是随机编号生成轮转赛程，再随机抽取所需轮次，避免独立随机配对造成重复或有人少打一场。
- 决赛重新编排，允许再次遇到初赛交手过的对手。
- 初赛结束按初赛成绩取前 30；决赛积分、胜局数、剪刀次数全部清零，按决赛成绩取前 10。
- 每阶段都按“总积分→剪刀次数→胜局数”依次降序排名，仍相同则随机抽签。
- 基本胜负仍是石头胜剪刀、剪刀胜布、布胜石头，同拳平局。
- 胜 2 分、平 1 分、负 0 分；每出一次剪刀额外加 1 分。
- 策略组只用于设置概率，不是比赛分组；每人每场按自己的固定概率独立出拳，不观察对手后出拳。

决赛清零让最终前 10 由决赛阶段的表现决定。初赛 5 场就淘汰 70 人，会比完整循环赛有更大的偶然性；增加初赛场次数可以缓解，不能完全消除随机对手带来的差异。

## 快速运行

所有人三种拳各有 1/3 概率，采用默认两阶段赛制：

```powershell
python rps_tournament.py --show-rounds
```

全体玩家统一设置概率，顺序为 **石头、剪刀、布**，概率之和必须为 1：

```powershell
python rps_tournament.py --probs 0.2 0.6 0.2 --seed 42 --show-rounds
```

给不同玩家设置不同策略，并重复 100 届：

```powershell
python rps_tournament.py --config strategies.example.json --runs 100 --seed 42 --out-dir results_bonus
```

配置示例包括 40 名均匀策略玩家、30 名偏剪刀玩家和 30 名偏石头玩家。
修改 JSON 中的组人数和概率即可；人数之和须为 100。也可以设置人数为 1 的策略组，单独指定某位玩家的概率。
`--show-rounds` 显示首届比赛每轮过程，不加此参数也会保存完整记录。

## 调整赛制

初赛改为每人 7 场，仍取前 30，决赛仍每人 9 场：

```powershell
python rps_tournament.py --prelim-rounds 7 --finalists 30 --final-rounds 9
```

此时总场数是 350 + 135 = 485 场。

如果希望决赛 30 人全部相遇一次，可改为：

```powershell
python rps_tournament.py --prelim-rounds 5 --finalists 30 --final-rounds 29
```

此时共 250 + 435 = 685 场。`--finalists` 必须是大于 10、小于 100 的偶数；每阶段场次数不能超过该阶段人数减 1。

## 随机种子与对照

相同种子、配置、赛制、奖励分和模拟次数会重现同一结果；每届和每阶段使用各自的随机流。
取消剪刀额外积分的对照命令：

```powershell
python rps_tournament.py --config strategies.example.json --runs 100 --seed 42 --scissors-bonus 0 --out-dir results_no_bonus
```

改奖励分不影响初赛的对阵、出拳和原始胜负；但会影响初赛晋级名单，因此决赛对阵和出拳记录也可能改变。
奖励设为 0 时，同分仍按剪刀次数、胜局数和随机抽签决定。

## 输出文件

默认写入脚本旁的 `simulation_results` 目录，可用 `--out-dir` 修改。再次使用同一目录会覆盖七个同名结果文件。

| 文件 | 内容 |
|---|---|
| `rankings.csv` | 首届全部 100 人的综合名次及最后参赛阶段成绩，`qualified=True` 表示进入前 10 |
| `stage_rankings.csv` | 首届初赛 100 人、决赛 30 人的阶段排名，共 130 行；`advanced=True` 表示通过该阶段 |
| `matches.csv` | 首届 385 场的阶段、轮次、双方出拳、胜者和得分；`winner=draw` 表示平局 |
| `rounds.csv` | 首届 14 轮的阶段、出拳数量、平局场数和本阶段累计最高分 |
| `player_summary.csv` | 全部模拟中每人的初赛晋级率、进入前十概率及其他统计 |
| `strategy_summary.csv` | 全部模拟中各策略组的初赛晋级率、进入前十概率及其他统计 |
| `summary.json` | 赛制参数、首届前 10 名和全部模拟的策略统计 |

上述行数对应默认赛制。各 CSV 使用带 BOM 的 UTF-8 编码，可用 Excel 打开。

综合名次先排决赛 30 人，再排初赛淘汰的 70 人；分别按决赛、初赛的阶段名次排序。
因此不能把 `rankings.csv` 中不同阶段的 `stage_points` 直接跨阶段比较。
`total_points` 是该玩家所有参赛阶段的积分合计，仅用于查看比赛过程，不用于决赛晋级。

统计字段的含义：

- `prelim_qualification_rate`：进入决赛人次 ÷ 参赛人次。
- `qualification_rate`：进入最终前 10 人次 ÷ 参赛人次。
- `conditional_final_qualification_rate`：进入最终前 10 人次 ÷ 进入决赛人次；未进过决赛时为空。
- `average_prelim_points`：每届初赛平均积分，所有人初赛场数相同，可以比较。
- `average_final_points`：只对进入决赛的届次计算决赛平均积分；未进过决赛时为空。
- `average_total_points`、`average_games`：每届所有实际参赛阶段的平均总积分、平均场数。
- `actual_scissors_rate`：全部实际剪刀次数 ÷ 全部实际出拳次数，不使用固定 99 场作为分母。

组统计的“参赛人次”是“组人数 × 模拟届数”。比率字段范围为 0 到 1。
因选手参赛场数不同，不宜只用 `average_total_points` 比较策略优劣，优先看进入前十概率。

## 附带示例结果

`simulation_results` 与 `simulation_no_bonus` 已更新为新赛制的实际输出：示例配置、种子 42、重复 100 届。

| 策略 | 奖励 1 分时进入决赛 | 奖励 1 分时进入前十 | 无额外积分时进入前十 |
|---|---:|---:|---:|
| 均匀策略 | 25.22% | 4.72% | 9.75% |
| 偏剪刀 | 50.13% | 24.87% | 9.87% |
| 偏石头 | 16.23% | 2.17% | 10.47% |

这是该配置下的有限次数模拟；其他出拳概率、场次数和随机种子可能得到不同结果。
剪刀奖励提高积分优势，不能保证多出剪刀就晋级。本脚本不模拟学习或观察历史后的策略调整。

查看全部参数：

```powershell
python rps_tournament.py --help
```
