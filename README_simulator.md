# 可配置石头剪刀布比赛模拟器

`rps_simulator.py` 支持自定义玩家策略、任意多阶段赛制、每阶段每人的比赛场次、晋级人数、胜平负积分、各手势加分，以及阶段之间清零或结转积分。需要 Python 3.10 或更新版本，只使用标准库，无需安装第三方包。

石头胜剪刀、剪刀胜布、布胜石头，同拳为平局。积分奖励影响排名，不会改变单局胜负。

完整包内附有 `example_report.html`，可先双击查看现成的三阶段比赛报告。主脚本、`rps_report.py` 和 `rps_report_template.html` 请放在同一文件夹内。

模拟结束会自动生成交互式可视化报告 `report.html`。运行时请将 `rps_simulator.py`、`rps_report.py` 和 `rps_report_template.html` 放在同一个文件夹；生成后的报告自包含，可以离线双击打开，也可以单独分享给别人，无需同时提供脚本或结果CSV。

## 快速开始

在脚本所在目录打开终端，运行：

```powershell
# 内置默认规则：100人均匀随机，5场取30人、9场取10人；生成并打开报告
python rps_simulator.py --open-report

# 先检查配置，不进行比赛
python rps_simulator.py --config simulator.advanced.json --validate-only

# 原始规则，模拟1000届，固定随机种子，指定结果目录
python rps_simulator.py --config simulator.original.json --runs 1000 --seed 42 --out-dir compare_original

# 剪刀每次加1分，模拟1000届，使用另一个结果目录
python rps_simulator.py --config simulator.scissors_bonus.json --runs 1000 --seed 42 --out-dir compare_bonus

# 看首届逐轮比赛过程，只模拟一届
python rps_simulator.py --config simulator.advanced.json --runs 1 --show-rounds

# 只输出CSV和JSON，不生成HTML报告
python rps_simulator.py --config simulator.original.json --runs 1000 --no-report

# 用已有结果目录重新生成报告并打开，不重新模拟
python rps_simulator.py --report-only compare_original --open-report

# 独立构建报告，也可指定HTML输出位置
python rps_report.py compare_original --output compare_original/report.html
```

`--runs` 和 `--seed` 会覆盖配置文件的同名字段。相同脚本、配置、参数和种子可以复现结果。比较规则时，请使用不同的 `--out-dir` 保存结果，避免后一次覆盖前一次输出。

正常模拟默认生成报告，但不自动打开浏览器；`--open-report` 会在生成后用默认浏览器打开。`--no-report` 与 `--open-report` 不能同时使用。`--validate-only` 只校验配置，不进行模拟或生成报告。

`--report-only RESULTS_DIR` 只读取已有结果来重建报告，可以与 `--open-report` 搭配；不能与 `--config`、`--runs`、`--seed`、`--out-dir`、`--show-rounds`、`--validate-only` 或 `--no-report` 同时使用。请保留完整的结果目录供重建报告使用。

## 可视化报告

在结果目录双击 `report.html`，可以查看：

- 策略组的最终入选率、单局胜率、非平局胜率、每局平均得分对比。
- 各阶段人数流转，以及分组的阶段条件晋级率。
- 首届比赛的积分分布和排名，按阶段、玩家组或玩家筛选。
- 按阶段与轮次选择首届对局，查看双方出拳、胜负和得分。

报告中的策略比较与阶段汇总覆盖全部 `runs`；积分分布、逐轮对局和排名只展示首届。报告已嵌入所需数据与页面代码，打开和交互均不需要联网。

| 示例文件 | 玩家构成 | 赛制 | 积分规则 |
|---|---|---|---|
| `simulator.original.json` | 40人均匀、30人偏剪刀、30人偏石头 | 100→30→10；每人5、9场 | 胜2、平1、负0，无手势奖励 |
| `simulator.scissors_bonus.json` | 与原始示例相同 | 与原始示例相同 | 胜2、平1、负0，出剪刀另加1分；同分优先比较剪刀次数 |
| `simulator.advanced.json` | 随机、固定、循环、模仿、反制混合，共100人 | 100→30→20→10；每人5、5、7场 | 每阶段可用不同规则，演示结转与清零 |

前两个示例每届385场；高级示例每届395场。它们都是完整示例，可复制后修改。

## 先区分“阶段”和“轮”

- **阶段（`stages`）**：结束时按积分筛选一次人，例如“初赛”“复赛”“决赛”。
- **轮（`rounds`）**：该阶段中的一轮配对，每个在场玩家打1局。每人打5场，就设置 `rounds: 5`。
- **晋级人数（`advance`）**：整个阶段结束后保留的人数。阶段内部不淘汰人，每人打完相同场次后统一排名。

每阶段公开随机配对，同阶段内不会重复遇到同一个对手，跨阶段可以再次相遇。配对不依据当前分数。设本阶段有 N 人，每人打 R 场，总场次为 `N × R ÷ 2`。

## 直接修改赛制

例如改为100人中选50人，再选20人，最后选10人：

```json
"stages": [
  {"name": "初赛", "rounds": 7, "advance": 50, "reset_scores": true},
  {"name": "复赛", "rounds": 7, "advance": 20, "reset_scores": true},
  {"name": "决赛", "rounds": 9, "advance": 10, "reset_scores": true}
]
```

每个阶段的 `name` 必须唯一。`rounds` 必须是1到本阶段人数减1之间的整数。初始人数必须为不小于2的偶数；后面还要比赛的阶段，其 `advance` 也必须为不小于2的偶数，不得超过本阶段人数。最后阶段的 `advance` 可以为1到本阶段人数之间的任意整数，例如选出冠军时设为1。

目前不设置轮空。增加每人场次有助于减少短赛程偶然性，同时也会增加比赛量。

## 设置玩家与出拳策略

根字段 `groups` 定义玩家组。组内每人采用同一份策略配置，但拥有各自独立的随机出拳和策略状态。所有组的 `count` 相加就是初始总人数。给某人单独设置策略时，新增 `count: 1` 的组即可。

所有手势都用以下英文值：

| 值 | 手势 |
|---|---|
| `rock` | 石头 |
| `scissors` | 剪刀 |
| `paper` | 布 |

### 随机策略：每局按概率独立抽取

```json
{
  "name": "偏剪刀",
  "count": 30,
  "strategy": {
    "type": "random",
    "probabilities": {"rock": 0.2, "scissors": 0.6, "paper": 0.2}
  }
}
```

概率必须非负、相加为1；需要填写三个手势。上例表示每次出拳有20%概率出石头、60%出剪刀、20%出布；不要求每5局恰好出3次剪刀。均匀随机可用示例文件中的三个近似三分之一数值。

为兼容旧配置，也接受组对象直接使用 `probabilities`、省略 `strategy` 的写法，新配置建议统一使用 `strategy`。

### 固定策略：一直出同一种拳

```json
"strategy": {"type": "fixed", "hand": "rock"}
```

### 循环策略：按指定顺序出拳

```json
"strategy": {
  "type": "cycle",
  "sequence": ["rock", "scissors", "paper"],
  "offset": 0,
  "reset_each_stage": true
}
```

每打1局往后移动一项，走到末尾后回到开头。`offset` 是非负整数，指定从序列的哪个位置开始；0表示第一项。序列可以包含重复手势，例如 `["scissors", "scissors", "rock", "paper"]`。

**循环策略不等于均匀随机。** 多名玩家使用相同序列和相同起点时，会同步出拳，彼此对战可能一直平局。可建立不同 `offset` 的组研究这一现象。

### 模仿上一场对手

```json
"strategy": {"type": "copy_last", "initial": "paper", "reset_each_stage": false}
```

没有历史时使用 `initial`，以后复制自己上一场遇到的对手所出的拳。注意，上一场对手通常不是当前对手。

### 克制上一场对手

```json
"strategy": {"type": "counter_last", "initial": "rock", "reset_each_stage": true}
```

没有历史时使用 `initial`，以后出能克制自己上一场对手手势的拳：上一场对手出石头，就出布；出剪刀，就出石头；出布，就出剪刀。

`copy_last` 和 `counter_last` 的 `initial` 默认是 `rock`。两种策略只使用已经结束的比赛信息，无法看到当前对手本局即将出的拳。

### 策略状态与阶段切换

`reset_each_stage` 默认 `true`。对循环策略，这意味着新阶段从配置的起点重新开始；对模仿和反制策略，意味着清除历史并重新使用 `initial`。设为 `false` 可让继续使用的策略延续上一阶段的进度或历史。每一届新比赛都会重新初始化所有人的策略状态。

同一组也可以在指定阶段换策略，`stage_strategies` 的键必须与阶段 `name` 完全一致；值是一份完整策略配置：

```json
{
  "name": "初期出剪刀，决赛改石头",
  "count": 10,
  "strategy": {"type": "fixed", "hand": "scissors"},
  "stage_strategies": {
    "决赛": {"type": "fixed", "hand": "rock"}
  }
}
```

未指定的阶段使用组的基础 `strategy`。修改策略不会改变该组的统计归属，结果仍按组的 `name` 汇总。
新阶段所用策略的 `reset_each_stage` 决定是否清除状态；即使切换了策略类型，设为 `false` 也会保留玩家已有的出拳计数和上一场对手手势。

## 设置胜平负积分与手势加成

根字段 `scoring` 是全局默认积分规则：

```json
"scoring": {
  "win": 2,
  "draw": 1,
  "loss": 0,
  "hand_bonus": {"rock": 0, "scissors": 1, "paper": 0}
}
```

单局所得分数 = 本局胜平负对应分数 + 本人所出手势的加成。加成在赢、平、输时都会发放；“加成”也可以为负数。

例如上述规则中，剪刀输给石头时，剪刀获得 `0 + 1 = 1` 分，石头获得 `2 + 0 = 2` 分；剪刀赢布时，剪刀获得 `2 + 1 = 3` 分。

积分支持负数和小数，例如 `loss: -0.5`、`paper: 0.25`。脚本使用十进制数精确累计和排名；评分字段也可写成十进制字符串，如 `"0.1"`。
单个评分最多支持28位有效数字，非零数值的数量级须在 `10^-100` 到 `10^100` 内。非法概率、拼错的字段、奇数参赛人数和超出范围的阶段场次会给出错误信息。

每阶段可写自己的 `scoring`，只覆盖需要变化的字段：

```json
{
  "name": "决赛",
  "rounds": 9,
  "advance": 10,
  "reset_scores": true,
  "scoring": {"win": 3, "hand_bonus": {"paper": 0.5}}
}
```

未写的胜平负字段和手势加成沿用**全局规则**，不会继承上一阶段的局部覆盖。在上述全局规则下，此决赛将采用胜3、平1、负0，石头加0、剪刀加1、布加0.5。

## 阶段积分清零与结转

`reset_scores` 默认为 `true`：开始本阶段前清零用于排名的积分和同分指标。设为 `false` 时，上一阶段保留下来的排名积分与指标继续累计。
第一阶段从0分开始，因此第一阶段设置为 `false` 也没有先前积分可结转。

三个积分字段的意义不同：

| 字段 | 含义 | 用途 |
|---|---|---|
| `stage_points` | 仅本阶段实际得到的积分 | 看本阶段表现 |
| `ranking_points` | 自最近一次清零以来累计、当前用于排名的积分 | 排名和晋级 |
| `total_points` | 该玩家本届所有实际参赛阶段得到的积分累计 | 统计，不会因清零消失 |

例如三阶段分别得到8、6、10分：

| 阶段 | `reset_scores` | `stage_points` | `ranking_points` | `total_points` |
|---|---|---:|---:|---:|
| 初赛 | `true` | 8 | 8 | 8 |
| 复赛 | `true` | 6 | 6 | 14 |
| 决赛 | `false` | 10 | 16 | 24 |

决赛结转的是复赛留下来的6分，再加决赛10分，**不会恢复初赛已经清除的8分**。同分比较用的胜场、平场和手势次数也按同一个“自最近一次清零以来”的区间累计。

`reset_scores` 和策略的 `reset_each_stage` 相互独立：可以清零分数但保留策略记忆，也可以结转积分但重置策略。

不同阶段使用不同分值又结转积分时，各阶段对总排名的权重也会变化；高级示例刻意展示了这一点。

## 设置同分排序

总积分 `ranking_points` 始终排第一优先级。只有同分时才按 `tie_breakers` 依次比较：

```json
"tie_breakers": ["scissors_count", "wins", "random"]
```

可选指标为：

| 指标 | 含义 |
|---|---|
| `wins` | 胜场更多者优先 |
| `draws` | 平场更多者优先 |
| `rock_count` | 出石头更多者优先 |
| `scissors_count` | 出剪刀更多者优先 |
| `paper_count` | 出布更多者优先 |
| `random` | 仍相同时随机抽签 |

指标均按从高到低排序。`random` 必须放最后；省略时脚本会自动补上。默认是 `["wins", "random"]`。在某阶段写 `tie_breakers` 可以替换该阶段的同分排序。

原始无奖励示例不会因为剪刀次数更多而优先晋级；剪刀奖励示例同时使用积分奖励与剪刀次数同分优先。若想只比较“每次出剪刀加1分”这一项的影响，请先把两个配置的 `tie_breakers` 改成一致。

## 结果文件与统计口径

默认输出到脚本旁的 `simulator_results` 目录，或用 `--out-dir` 自定义。正常模拟生成以下9个文件；使用 `--no-report` 时只生成前8个数据文件：

| 文件 | 内容 |
|---|---|
| `rankings.csv` | 首届最终总排名与最终入选状态 |
| `stage_rankings.csv` | 首届每个阶段的排名与晋级状态 |
| `matches.csv` | 首届逐局记录：对手、出拳、胜负与得分 |
| `rounds.csv` | 首届各阶段每轮的比赛汇总 |
| `player_summary.csv` | 全部模拟届数中，每位玩家的表现与最终晋级统计 |
| `strategy_summary.csv` | 全部模拟届数中，按配置玩家组汇总的表现 |
| `stage_summary.csv` | 每阶段的实际参赛、阶段晋级统计，包含全体及各组 |
| `summary.json` | 全部模拟的配置、赛制与汇总结果 |
| `report.html` | 可离线打开、筛选和分享的自包含可视化报告 |

过程文件只保留首届，避免多届模拟产生大量逐局数据；汇总文件统计所有 `runs`。

CSV 积分使用十进制文本。JSON 中的积分和积分平均值也使用十进制字符串表示（包括整数积分），以保留精度；计数与比率仍为数值。用其他程序读取时按需要转换为数值。

理解结果时要区分：

- **单局胜率**：胜局数 ÷ 实际打过的总局数，平局包含在分母内。它不是最终晋级率。
- **非平局胜率**：胜局数 ÷（胜局数 + 负局数），排除平局；应结合平局率和实际局数一起看。
- **最终晋级率**：最终进入最后阶段前 `advance` 名的次数 ÷ 相应的参赛人次。100人最终选10人时，全体平均为10%，某组可能高于或低于10%。
- **阶段晋级率**：在实际进入该阶段的条件下，该阶段晋级人次 ÷ 该阶段参赛人次。没有进入决赛的人不会被计入决赛参赛分母。

晋级的人会多打后续阶段的比赛，所以各组的累计局数通常不同。比较策略时，请同时看按**实际局数**计算的胜率、平均得分，以及阶段/最终晋级率，不要仅用总胜场或总得分判断优劣。阶段策略会变化时，阶段汇总也比全届混合统计更有解释力。

## 如何解读“什么影响获胜”

若自己出石头、剪刀、布的概率为 `p_rock`、`p_scissors`、`p_paper`，当前对手的对应概率为 `q_rock`、`q_scissors`、`q_paper`，则单局胜率为：

```text
P(赢) = p_rock × q_scissors
      + p_scissors × q_paper
      + p_paper × q_rock
```

当对手独立均匀随机时，任何固定出拳策略的单局胜率都是三分之一。偏剪刀是否有利，取决于实际对手中出布与出石头的比例。

加分后，单局胜率与积分优势可能不同：剪刀即使输局也可以得奖励分，因此原始胜率较低的策略仍可能有更高晋级率。除此之外，玩家构成、随机配对、每阶段比赛场数、阶段清零、同分排序、后续阶段对手构成都会影响最终入选。

建议每次只改变一个因素，重复模拟至少数百届，再比较汇总结果。相同种子方便复现，但两种规则一旦选出不同的晋级者，后续对阵与出拳序列也会变化，不能把两份结果理解为每一局都严格相同的配对实验。

模拟不包含合谋、故意输局、观察全体玩家后学习、针对当前对手单独建模等行为。`counter_last` 只克制上一场对手的历史出拳，不代表能预测当前对手。
